# Progress — 2026-09-22

Eval of the Vulkan compute pipeline (`daemon/src/pipeline.rs`, commit

## Pipeline: was it done correctly?

Yes, as a **compute dispatch layer**. The module does the thing its comment
says: allocate the SSBOs/UBOs the shaders expect, compile SPIR-V at build
time (`build.rs` + `glslangValidator`), bind descriptors, record projection
then eviction in one command buffer with an explicit compute→compute
barrier, submit, fence-wait, host-read projected output. Layout math in
`gpu_layout.rs` is tested against std140/std430 (`memoffset`), and the
live smoke tick on this machine matched the camera arithmetic exactly.

It was **not** wired when it landed. `main.rs` had no `mod pipeline`, so
`cargo build` did not even typecheck the new file. The module comment
referred to a startup smoke test in `main.rs` that did not exist. That is
now fixed: `mod pipeline` + `pipeline::smoke_tick` on daemon start, fatal
if dispatch fails.

### What is good

- Build-time SPIR-V embed (`include_bytes!` of `OUT_DIR`) — no runtime
  shader path hunting.
- Persistent `HOST_VISIBLE | HOST_COHERENT` maps, documented as the
  simplicity-first tradeoff (right for this milestone; wrong as a final
  discrete-GPU path).
- Command buffer recorded once; uniforms/splats updated in mapped memory;
  re-submit. Valid Vulkan.
- Barrier between projection (writes `last_visible_frame`) and eviction
  (reads it) is a real GPU-GPU hazard they did not skip.
- Fence wait before host readback. `HOST_COHERENT` + wait is enough here.
- Bone palette defaults to identity dual-quats; unrigged splats bound to
  bone 0 stay still until posed.
- `vkResetFences` on a newly created unsignaled fence is legal (not pending).
- Graphics queue used for compute: spec-correct (`GRAPHICS` implies
  `COMPUTE`); they noted a dedicated async-compute queue as a later option.

### What to improve (do not redesign)

1. **Keep the pipeline alive.** Smoke constructs, ticks, destroys. Actors
   still print. Next: one `SplatPipeline` owned for the process lifetime,
   `write_splat` from Control/Presence/Ingress, a tick (timer or dirty
   flag) — not a second pipeline implementation.
2. **No raster, no surface.** Projected output is CPU-readable numbers.
   Nothing hits Hyprland. Overlay is still the product gap.
3. **Explicit `destroy()`, no `Drop`.** Easy to leak if a future caller
   forgets; `VulkanContext::Drop` will then destroy the device with
   pipeline objects still live. Implement `Drop` for `SplatPipeline` or
   invert ownership so the pipeline owns (or shares) the device.
4. **Host-visible storage for GPU-written buffers.** Fine for smoke
   readback. A renderer wants `DEVICE_LOCAL` projected output and no
   round-trip. Split “debug readback” from “live buffer” when overlay
   exists.
5. **First physical device wins.** This laptop’s `[0]` is Iris Xe and it
   worked. Prefer discrete when present; optional `VK_LAYER_KHRONOS_validation`
   in debug builds would have caught descriptor mistakes cheaper than a
   smoke tick.
6. **Bone index vs `MAX_BONES` (64).** Skinning weights can name joint 7
   today; the SSBO is 64 dual-quats. Clamp or reject at `write_splat`.
7. **Eviction `count` can exceed 256.** Shader `atomicAdd`s then bounds
   the write. `evicted_texture_count()` should `min(count, MAX_EVICTIONS)`.
8. **Near-clip `z < 0.1` plus identity camera** means a splat at the
   origin silently produces a zeroed `ProjectedSplat` (id 0, depth 0) —
   indistinguishable from “empty” unless the caller tracks live indices
   (they documented this). Smoke avoids it by placing z=2; callers must too.
9. **No validation that `ProjectionUniforms.total_capacity` matches the
   allocated buffer.** `set_projection_uniforms` is fully caller-trust.
10. **`gltf_to_splat.comp` is still not in `build.rs`.** Correct for now
    (not dispatched). Don’t let it rot uncompiled.

Not bugs, just the next layer: ingress still not ticked, text-to-pose
still zeros, MCP PolicyGate still per-process, socket still one client at
a time.

# Progress — 2026-09-19

Eval of feasibility, architecture, coding approach, and what's actually
built, plus the small architecture fixes and the next-step sequence.
Written after reading the MCP binding, daemon, shaders, ingress backends,
and docs — not after running the daemon on hardware.

The Vulkan dispatch loop / pipeline module was already in flight when this
was written. Anything in **Parallel to the pipeline** is scoped to stay off
that work.

## Snapshot

The six-tool contract is the strongest thing in the repo, and it already
runs: an agent CLI can propose presence today. The daemon is a well-built
front door plus a GPU *sketch* — Vulkan device, protocol, splat I/O, DQB
shaders, V4L2/wlr-screencopy clients — not yet a presence runtime. Nothing
pixels-out is composited. MCP still talks to `notify-send`.

Three phases, uneven feasibility:

| Phase | What | Feasible? |
|---|---|---|
| 1 | Agent-provided Gaussian-splat avatars, daemon-owned animation | **Yes**, as an engineering finish: overlay + load one cloud + a placeholder pose mapper. DQB of a canonical cloud is the right bet. |
| 2 | Avatars conditioned on content + webcam + mic; auto-animate speech | **Different system.** Billboard-as-splat is a good interim for camera/screen. Audio, visemes, and a clock are missing. `animatePresence(text)` is a semantic poke, not a speech timeline. |
| 3 | Model sits inside the runtime on a Linux box | **Destination, not a sprint.** MCP is correctly a bridge. Requires a tick loop, shared process-level state, and an on-device inference slot the daemon does not have. |

Do not let phase-3 vocabulary (Field / State / Perceptual Memory / Temporal
Resource Ledger) delay a visible overlay.

## What's real vs sketched

**Real and callable**

- Six Manifestations + skill + `presence` CLI (`setup claude/codex/grok`, `doctor`)
- Policy gate (per MCP process): 1.5s interval, 3 presences, 20 artifacts
- Daemon: Vulkan instance/device, dma_buf extension probe, Unix socket, JSONL protocol matching the tools
- Control / Presence actors + Scene Memory (canonical rest-pose cloud, optional skinning)
- `.splat` and 3DGS PLY loaders; `AnimatedSplat` 96-byte GPU layout with tests
- Compute shaders (projection, eviction, glTF-to-splat, DQ math) compile-checked; several real shader bugs already fixed
- Ingress: `frame_to_billboard`, V4L2 ioctl client, `wlr-screencopy` SHM client — compile-verified, never opened a compositor or `/dev/video0` from this tree

**Sketched or unwired**

- MCP Binding still imports `daemonStub.ts`, not the socket
- No compute dispatch, no SSBO allocation, no SPIR-V pipeline in `main.rs`
- No Wayland surface / `wlr-layer-shell` / raster pass (a `VkDevice` is not an overlay)
- `text_to_pose_code` returns zeros
- Ingress backends never ticked
- Highlight is still a print: resolving "the red error banner" is a VLM problem, not a shader
- Multi-agent "shared substrate" is design-only: each agent spawns its own Node process with its own PolicyGate; socket is one connection at a time

~3k lines of TS/Rust/GLSL across `src/` + `daemon/src` + `daemon/shaders`. Honest comments about unbuilt pieces are a feature; `daemon/README.md` has drifted behind `actors/ingress/` (still lists webcam/screen as "what's next").

## Architecture — keep it; a few load-bearing fixes

The two-process split, "messages describe, don't carry pixels", frozen tool
list, and "text is intent / daemon owns motion" are right. No redesign.
The architecture improvements are about making those claims true in the
process graph:

1. **Shared state belongs in the daemon.** Caps, live IDs, and "another agent can see this presence" cannot live in a per-CLI `PolicyGate`. Node remains the typed front door; the registry is the substrate.
2. **The socket must accept concurrent connections.** One-at-a-time contradicts the multi-agent story. Protocol stays JSONL; the server should not serialize the world on a single stream.
3. **One ID authority — the daemon.** Binding-side `Math.random()` IDs will collide across processes and cannot reattach after MCP restart. Client proposes; daemon returns the id.
4. **Policy: never rate-limit retire.** 1.5s on `animatePresence` is also too coarse for live driving (one budget shared across all presences). Rate-limit spawn/highlight if you want a brake; don't trap teardown.
5. **Be honest that capture is SHM first.** Architecture.md sells V4L2 `EXPBUF` + `VkImportMemoryFdInfoKHR`. The working screencopy client copies into `wl_shm`. Fine as v0; not the zero-copy path `vulkan.rs` is probing. Don't let those get conflated.
6. **`addArtifact` is a path, not a blob.** Under "describe, don't carry" the daemon reads a local `.splat`/`.ply`. The skill must say: write a file, then pass `sourceUri`. A description-only call currently stores an empty cloud and looks like success.
7. **Audio needs a clock, not another tool.** Microphone ingress is named in vision.md and absent in code. PipeWire in, visemes onto ~10 pose params, TTS/playback on the daemon's timeline. `animatePresence(text)` sets *what* to say.
8. **Keep Linux out of the core.** Empty traits (or modules) for Field / State / Perceptual Memory / mic *now*, so V4L2 and wlr types cannot leak into `registry.rs` before a second binding (AppFunctions, etc.) exists.

Not architecture so much as ingest reality: agents do not emit Gaussian
clouds. Phase 1 needs a stated path — a captured 3DGS, or a reconstruction
model beside the daemon. A 2D image is not a splat.

## Coding approach

Keep: dlopen-so-CI-compiles (`ash`, wayland), FFI sized against real
headers (the V4L2 `align(8)` union bug), shader math fixed under
`glslangValidator` (missing DQ terms, antipodal blend), rigid-bind-to-bone-0
as the unrigged default, tests on GPU layout / billboard packing / loaders.

Change: Node side has no tests (policy + protocol lockstep is where the
bugs will be). Comments in `splat_io.rs` still say `GaussianSplat` stores
covariance; it stores scale+rotation. Don't grow the tool list to paper
over missing daemon behavior.

## Next steps (sequenced, after / around the pipeline)

The pipeline module owns: buffer allocation, SPIR-V, per-frame compute
dispatch, eventually raster. Do not compete with that. The visible product
still needs these, in order:

1. **MCP → Unix socket** (`daemonClient.ts`, fall back to stub if the socket is missing). Highest-leverage glue; unblocks everything else from an agent session.
2. **Something on a Hyprland overlay** — even a colored quad on `wlr-layer-shell`. Until a human can see it, the avatar story is still a notification. (Depends on pipeline + a surface; pipeline author likely owns this seam.)
3. **Load one splat into the live buffer** and draw it. Proves Control → Scene Memory → GPU layout end to end.
4. **Tick screen billboard** (one `AnimatedSplat`, refresh `last_visible_frame`). Webcam after that.
5. **Placeholder pose table in the daemon** so `animatePresence` moves *something* without waiting for the research text-to-pose model. Keep the contract as text.
6. **Then** audio clock / visemes; highlight-as-VLM; reconstruction ingest; on-device model slot.

Do not start highlight grounding, JEPA, or a second tool in parallel with
(1)–(5). Highlight is perception. Overlay is compositing. Different
milestones.

## Parallel to the pipeline — what I'd take

Stay out of `daemon/src/vulkan.rs`, shaders, `gpu_layout.rs`, and any new
dispatch/pipeline module. Useful work that does not collide:

- Wire `src/daemonClient.ts` and keep the stub as fallback (this is the
  MCP-side half of "what's next" in `daemon/README.md`).
- Exempt `retirePresence` / `retireArtifact` from the 1.5s gate; leave
  spawn/highlight limited.
- Skill + README: `sourceUri` is a local `.splat`/`.ply` path; description-only
  holds an empty cloud.
- JSONL test vectors both Node and Rust parse (lockstep without generating
  the protocol yet).
- Refresh `daemon/README.md` so ingress isn't listed as unbuilt.
- Run `presence-daemon` on this Omarchy box (Vulkan + dma_buf probe) and
  record the doctor output — the ingress "never opened a display" caveat is
  about a sandbox, not this machine.
- Multi-connection socket *if* it can be done without rewriting the accept
  loop the pipeline tick will sit in; otherwise wait.
- Empty `actors/audio.rs` / microphone trait so "ears" have a type to fill.
  No PipeWire implementation until the overlay exists.

What I would not do while the pipeline is open: touch compute shaders,
invent a rasterizer, add MCP tools, or start a text-to-pose model.
